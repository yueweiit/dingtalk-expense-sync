# 已全额抵扣规则

## 规则

只有配置在 `DINGTALK_PAYMENT_EVENT_USER_IDS` 中的用户，单独评论 `已全额抵扣` 时，才生成 `fully_deducted`（全额抵扣）事件。

该事件的原币金额和人民币本位币金额固定为 `0`。它表示单据已经处理，但没有实际支出，因此会阻止整单完成金额兜底，也不会增加预算已用金额。评论中的原文、用户和时间仍会保存用于审计，事件继续按业务编号、评论时间和来源哈希幂等。

如果同一条评论同时包含 `已全额抵扣` 与 `已支付`、`部分支付` 或金额，不自动入账，等待人工复核。工资、社保、公积金、办公场地、个税和 IT 运维等实际存在部门拆分的表单继续使用部门拆分规则，不创建整单付款事件。

## 数据库兼容

`approval_expense_payment_events.source_type` 新增 `fully_deducted`；只有此类型允许 `amount = 0`，其他付款事件仍要求正金额。部署前执行 `sql/ensure_approval_expense_schema.sql`，该脚本只调整约束，不修改业务数据。

## 跨项目要求

`dingtalk-expense-sync` 负责识别和写入事件；`dingtalk-budget` 的列表、详情、报表、周报和 Excel 必须将该事件视为已处理的零元事实，并排除完成态整单金额兜底；`dingtalk-oa` 继续只保存钉钉原始审批和评论，不需要业务代码修改。
